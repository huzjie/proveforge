# 攻击模型与检测

proveforge 内置三类攻击变体，分别对应可验证推理要防的三种造假：

## 1. 替换模型（substitution）

路由服务/证明者用一个更便宜、独立的模型 B 顶替承诺模型 A。

- **行为**：用 B 解码、揭示 B 的权重，但对外仍声称是 A。
- **被谁抓**：绑定检查。B 的权重哈希不到 A 的承诺根。
- **指标**：`binding`（低）、`substitution_detection`（高）。

## 2. 篡改 token（tampering）

中间人把输出流里的某个 token 改掉。

- **行为**：用 A 正常解码，但声称的输出 token 与轨迹里的 argmax 不一致。
- **被谁抓**：完整性检查。`argmax(logits) != 声称的 token`、`output_tokens[i] != trace[i].token`。
- **指标**：`integrity`（低）、`tamper_detection`（高）。

## 3. 伪造轨迹（malformed trace）

证明者报告一条与权重不符的「假执行轨迹」。

- **行为**：篡改某一步的某个激活值，使 `dot(打开行, 输入激活) != 下一层激活`。
- **被谁抓**：完整性检查（点积关系）。
- **指标**：`integrity`（低）。

## 局部投毒与声音性曲线

「偷换整个模型」太容易被抓（几乎每行权重都变），真实攻击更隐蔽：只改少数几行权重（局部投毒）。当验证器只选择性打开部分行时，能否命中投毒行就取决于打开比例——这正是声音性曲线（`bench` 的 `soundness sweep`）展示的东西。

## 防御思路（可复用）

1. **承诺前置**：先承诺后服务，让「偷换」从「不可检测」变成「验证即暴露」。
2. **挑战不可预测**：Fiat-Shamir 用 `H(承诺||prompt||输出||轨迹)` 选挑战，证明者无法预知抽查点。
3. **非对称成本**：证明贵、校验便宜，审计方用普通 CPU 即可复核，无需信任提供方。
4. **抽查比例 = 声音性**：对高价值请求提高 `open_ratio`，用更多证明成本换更高保证。
